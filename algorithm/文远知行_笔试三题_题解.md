## 第二题：放置一个障碍物使机器人回到原点

### 题意

给定由 `L`、`R`、`U`、`D` 构成的指令串，机器人从 `(0, 0)` 出发，依次执行指令。

现在可以在一个整数坐标 `(x, y)` 放置障碍物：当某一步的目标位置恰好是障碍物时，机器人该步原地不动；其他指令仍照常执行。求任意一个能让机器人最终回到 `(0, 0)` 的障碍物坐标。无解时输出 `0 0`。

题目保证所有测试用例中字符串总长度不超过 `5000`。

### 先理解一次移动

以当前位置 `(x, y)` 为例：

- `L` 的目标位置是 `(x-1, y)`；
- `R` 的目标位置是 `(x+1, y)`；
- `U` 的目标位置是 `(x, y+1)`；
- `D` 的目标位置是 `(x, y-1)`。

如果这个目标位置恰好等于障碍物，机器人**不会移动**，仍停在 `(x, y)`；否则才更新到目标位置。障碍物不会被撞坏，也不会阻止机器人经过其他位置。

### 关键结论：候选障碍物只需来自原始轨迹

若障碍物从未被机器人尝试进入，它不会影响运动结果。因此，存在有效障碍物时，必然可以选取为“不放障碍物时，机器人某一步到达的坐标”。

更严格地说，假设障碍物 `p` 能改变运动结果，设第一次因为 `p` 而没有移动的指令为第 `k` 步。在前 `k-1` 步中，障碍物尚未生效，机器人轨迹与不放障碍物时完全相同；第 `k` 步的目标位置就是 `p`。所以 `p` 一定在原始轨迹中出现过。

这就把无限多个整数坐标的枚举，缩小到最多 `|s|` 个候选坐标。

所以只需：

1. 先模拟一次，收集所有经过的非原点坐标，作为候选障碍物；
2. 对每个候选点重新模拟整段指令；
3. 若最终回到原点，立即输出该候选点。

候选点数不超过字符串长度，因此复杂度为 `O(|s|^2)`；在总长度不超过 `5000` 时可通过。

### 完整示例：`RUULLD`

不放障碍物时，轨迹如下：

| 步骤 | 指令 | 位置 |
| --- | --- | --- |
| 初始 | - | `(0, 0)` |
| 1 | `R` | `(1, 0)` |
| 2 | `U` | `(1, 1)` |
| 3 | `U` | `(1, 2)` |
| 4 | `L` | `(0, 2)` |
| 5 | `L` | `(-1, 2)` |
| 6 | `D` | `(-1, 1)` |

最终不在原点，因此需要尝试候选点。取障碍物 `(1, 1)` 后重新模拟：

| 步骤 | 指令 | 目标位置 | 实际位置 | 原因 |
| --- | --- | --- | --- | --- |
| 初始 | - | - | `(0, 0)` | - |
| 1 | `R` | `(1, 0)` | `(1, 0)` | 不撞障碍物 |
| 2 | `U` | `(1, 1)` | `(1, 0)` | 目标是障碍物，原地不动 |
| 3 | `U` | `(1, 1)` | `(1, 0)` | 仍被障碍物阻挡 |
| 4 | `L` | `(0, 0)` | `(0, 0)` | 正常移动 |
| 5 | `L` | `(-1, 0)` | `(-1, 0)` | 正常移动 |
| 6 | `D` | `(-1, -1)` | `(-1, -1)` | 正常移动 |

该候选点不能让机器人回到原点，继续枚举其他原始轨迹中的点即可。算法并不依赖“障碍物只会阻挡一次”：同一个障碍物可以阻挡多次，这也是必须完整重放所有指令的原因。

### 一个能成功的示例：`RUDLR`

不放障碍物时，轨迹为 `(1,0) -> (1,1) -> (1,0) -> (0,0) -> (1,0)`，最终在 `(1,0)`，没有回到原点。

选择候选障碍物 `(1,0)` 并重新模拟：第一步 `R` 的目标正好是障碍物，机器人留在 `(0,0)`；后续 `U -> D -> L -> R` 分别到达 `(0,1) -> (0,0) -> (-1,0) -> (0,0)`。最终回到原点，所以输出 `1 0`。

### 边界情况

- 指令串只有一个方向，例如 `RRR`：任何障碍物至多减少向右位移，无法产生向左位移，通常无解。
- 某个坐标被多次经过：候选集合去重即可；重放时该障碍物仍可能阻挡多次。
- 原点不能作为障碍物候选：题意要求障碍物坐标不能是起点 `(0,0)`，代码用 `p != (Point{})` 排除。若最终输出 `0 0`，它表示“没有可用的障碍物方案”，而不是实际在原点放障碍物。
- 多组数据总长度最多 `5000`：`O(|s|^2)` 的暴力重放可接受，不需要更复杂的数据结构。

### Go 参考实现（快速输入输出）

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

type Point struct {
	x, y int
}

func solve(s string, out *bufio.Writer) {
	candidates := make([]Point, 0, len(s))
	seen := make(map[Point]bool, len(s))

	// 不放障碍物时经过的位置，才可能成为有效障碍物。
	x, y := 0, 0
	for i := 0; i < len(s); i++ {
		switch s[i] {
		case 'L':
			x--
		case 'R':
			x++
		case 'D':
			y--
		case 'U':
			y++
		}
		p := Point{x, y}
		if p != (Point{}) && !seen[p] {
			seen[p] = true
			candidates = append(candidates, p)
		}
	}

	for _, obstacle := range candidates {
		x, y = 0, 0
		for i := 0; i < len(s); i++ {
			nx, ny := x, y
			switch s[i] {
			case 'L':
				nx--
			case 'R':
				nx++
			case 'D':
				ny--
			case 'U':
				ny++
			}
			if nx != obstacle.x || ny != obstacle.y {
				x, y = nx, ny
			}
		}
		if x == 0 && y == 0 {
			fmt.Fprintln(out, obstacle.x, obstacle.y)
			return
		}
	}

	fmt.Fprintln(out, "0 0")
}

func main() {
	in := bufio.NewReaderSize(os.Stdin, 1<<20)
	out := bufio.NewWriterSize(os.Stdout, 1<<20)
	defer out.Flush()

	var t int
	if _, err := fmt.Fscan(in, &t); err != nil {
		return
	}
	for ; t > 0; t-- {
		var s string
		fmt.Fscan(in, &s)
		solve(s, out)
	}
}
```

## 第三题：自动驾驶路线验证

### 题意

G 市有 `N` 个城市（编号为 `1` 到 `N`）和 `M` 条无向道路。文文从 `1` 号城市出发，希望每条道路恰好经过一次。判断是否存在这样的路线。

这是起点固定为 `1` 号城市的无向图欧拉路径问题。

### 判定条件

这题是**无向图**：读入一条道路 `u v` 后，代码同时加入 `u -> v`、`v -> u`，因此道路可从任一端通过。它不是有向图。

对于无向图，忽略孤立点后，所有有边的顶点必须处于同一个连通块；否则不可能从 `1` 号点出发，用一条连续路线覆盖所有边。这里不要求所有城市都连通，例如 `4` 号城市没有任何道路时，它不会影响答案。

若题目改成有向道路，不能直接沿用本题代码：需要用入度、出度的差值判定起终点，还要检查有向图的可达性。本题的 `deg[u]++`、`deg[v]++` 正是无向图度数的统计方式。

在此基础上：

- 所有顶点度数均为偶数：存在从 `1` 号点出发并回到 `1` 号点的欧拉回路；
- 恰有两个奇数度顶点且 `1` 号点为奇数度：存在从 `1` 号点出发、终止于另一个奇数度点的欧拉路径；
- 其余情况均不满足条件。

特别地，`M == 0` 时无需经过道路，直接输出 `YES`。

### 从代码看无向图与连通性

读入一条道路 `u v` 时，代码执行：

```go
g[u] = append(g[u], v)
g[v] = append(g[v], u)
```

这表示同一条道路在 `u`、`v` 两端各存一次。因此从 `u` 可以走到 `v`，从 `v` 也可以走到 `u`，即无向图。

题目并不是要求每个编号为 `1..N` 的点都能互通，而是要求**所有存在道路的点**与 `1` 号点连通。比如：

```text
1 -- 2 -- 3      4
```

`4` 是孤立点，没有需要经过的道路；只要 `1-2`、`2-3` 能满足奇偶度条件，`4` 不会让答案变成 `NO`。但若存在另一条独立道路：

```text
1 -- 2      3 -- 4
```

就一定是 `NO`，因为走完 `1-2` 后无法跳到 `3-4`。

### 为什么这两个条件足够

欧拉路径有两个限制：路线不能“跳跃”，且每条边只能经过一次。

- **连通性**保证路线可以连续地覆盖全部道路。例如边为 `1-2`、`3-4`，即使四个点的度数都是奇数/偶数条件恰好满足，仍不能从 `1` 走到 `3-4` 这部分，所以输出 `NO`。
- **奇数度个数**决定路线的起终点。每次经过一个中间点，都会“进一次、出一次”，使用两条相邻边，贡献是偶数；只有路径的起点和终点可以各多使用一条边，因此奇数度顶点只能有 `0` 或 `2` 个。

例 1：道路为 `1-2`、`2-3`、`3-1`。三个点度数均为 `2`，可走 `1 -> 2 -> 3 -> 1`，输出 `YES`。

例 2：道路为 `1-2`、`2-3`。`1` 和 `3` 的度数为 `1`，`2` 的度数为 `2`，可走 `1 -> 2 -> 3`，输出 `YES`。因为 `1` 是两个奇数度点之一，正好能作为起点。

例 3：道路为 `1-2`、`1-3`、`1-4`。共有四个奇数度点，无法只用一条不重复道路的路线走完，输出 `NO`。

例 4：道路为 `1-2`、`2-3`、`3-4`。奇数度点只有 `1` 和 `4`，可走 `1 -> 2 -> 3 -> 4`，输出 `YES`；如果道路改为 `2-1`、`2-3`、`3-4`（无向边写法等价），结论不变。

例 5：道路为 `1-2`、`2-3`、`3-1`、`3-4`。`3` 与 `4` 是奇数度点，虽然奇数度点恰好为两个，但起点 `1` 的度数为偶数，不能从 `1` 出发一次走完所有边，因此输出 `NO`。实际可行路线必须从 `3` 出发、在 `4` 结束。

### `edgeCount != 2 * m` 的含义

无向边 `u-v` 被存了两次：一次在 `g[u]`，一次在 `g[v]`。DFS 从 `1` 出发时，每遍历一个邻接表元素就执行一次 `edgeCount++`。

因此，如果全部 `m` 条道路都属于 `1` 所在连通块，所有邻接表元素恰好会被扫描 `2 * m` 次。若 `edgeCount < 2 * m`，说明有一些道路在另一个连通块中，无法从 `1` 到达，输出 `NO`。

这不是“某个点的度数等于边数两倍”。单个点的度数是与该点相连道路数；`edgeCount` 是 DFS 扫描到的**整个连通块的邻接表项总数**。例如三角形 `1-2`、`2-3`、`3-1` 有 `m = 3`，每个点度数为 `2`，而 DFS 的 `edgeCount` 为 `6 = 2 * m`。

也可以不计数，而是在搜索结束后枚举所有点，检查每个 `deg[i] > 0` 的点是否都被访问。两种写法等价；本题代码的 `edgeCount == 2*m` 写法更紧凑。

### Go 参考实现（快速输入输出）

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

func solve(in *bufio.Reader, out *bufio.Writer) {
	var n, m int
	if _, err := fmt.Fscan(in, &n, &m); err != nil {
		return
	}

	deg := make([]int, n+1)
	g := make([][]int, n+1)
	for i := 0; i < m; i++ {
		var u, v int
		fmt.Fscan(in, &u, &v)
		deg[u]++
		deg[v]++
		g[u] = append(g[u], v)
		g[v] = append(g[v], u)
	}

	if m == 0 {
		fmt.Fprintln(out, "YES")
		return
	}
	if deg[1] == 0 {
		fmt.Fprintln(out, "NO")
		return
	}

	// 统计 1 号点所在连通块中的边数。
	vis := make([]bool, n+1)
	edgeCount := 0
	var dfs func(int)
	dfs = func(u int) {
		vis[u] = true
		for _, v := range g[u] {
			edgeCount++
			if !vis[v] {
				dfs(v)
			}
		}
	}
	dfs(1)
	if edgeCount != 2*m {
		fmt.Fprintln(out, "NO")
		return
	}

	odd := 0
	for i := 1; i <= n; i++ {
		if deg[i]%2 != 0 {
			odd++
		}
	}
	if odd == 0 || (odd == 2 && deg[1]%2 != 0) {
		fmt.Fprintln(out, "YES")
	} else {
		fmt.Fprintln(out, "NO")
	}
}

func main() {
	in := bufio.NewReader(os.Stdin)
	out := bufio.NewWriter(os.Stdout)
	defer out.Flush()

	var t int
	if _, err := fmt.Fscan(in, &t); err == nil {
		for i := 0; i < t; i++ {
			solve(in, out)
		}
	}
}
```

建图与连通性检查的时间复杂度为 `O(N + M)`，空间复杂度为 `O(N + M)`。

### BFS 版本（同样正确）

可以。DFS 与 BFS 都只是用于检查“从 `1` 号点是否能覆盖全部道路所在的连通块”，两者的复杂度均为 `O(N + M)`。下面是仅将 DFS 改成 BFS 后的完整实现，奇数度判定保持不变。

选择建议：本题的 DFS 代码更直观；但当图可能是一条很长的链、顶点数很大时，Go 的递归 DFS 有栈深风险，BFS 使用显式队列更稳妥。两者不改变欧拉路径的判定结果。

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

func solve(in *bufio.Reader, out *bufio.Writer) {
	var n, m int
	if _, err := fmt.Fscan(in, &n, &m); err != nil {
		return
	}

	deg := make([]int, n+1)
	g := make([][]int, n+1)
	for i := 0; i < m; i++ {
		var u, v int
		fmt.Fscan(in, &u, &v)
		deg[u]++
		deg[v]++
		g[u] = append(g[u], v)
		g[v] = append(g[v], u)
	}

	if m == 0 {
		fmt.Fprintln(out, "YES")
		return
	}
	if deg[1] == 0 {
		fmt.Fprintln(out, "NO")
		return
	}

	vis := make([]bool, n+1)
	queue := []int{1}
	vis[1] = true
	edgeCount := 0
	for head := 0; head < len(queue); head++ {
		u := queue[head]
		for _, v := range g[u] {
			edgeCount++
			if !vis[v] {
				vis[v] = true
				queue = append(queue, v)
			}
		}
	}
	if edgeCount != 2*m {
		fmt.Fprintln(out, "NO")
		return
	}

	odd := 0
	for i := 1; i <= n; i++ {
		if deg[i]%2 != 0 {
			odd++
		}
	}
	if odd == 0 || (odd == 2 && deg[1]%2 != 0) {
		fmt.Fprintln(out, "YES")
	} else {
		fmt.Fprintln(out, "NO")
	}
}

func main() {
	in := bufio.NewReader(os.Stdin)
	out := bufio.NewWriter(os.Stdout)
	defer out.Flush()

	var t int
	if _, err := fmt.Fscan(in, &t); err == nil {
		for i := 0; i < t; i++ {
			solve(in, out)
		}
	}
}
```
